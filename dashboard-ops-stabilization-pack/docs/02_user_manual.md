# 02. 8축 시장 대시보드 사용 매뉴얼

## 1. 대시보드 목적

이 웹사이트는 단순한 경제지표 표시판이 아니라, 시장을 8개 축으로 나누어 자금 흐름과 리스크 균형을 판단하기 위한 개인 운용 시스템이다.

8축은 다음과 같다.

```text
1. 금리/유동성
2. 기업 실적/가이던스
3. 자금 흐름
4. 고용/경기 사이클
5. 소비/수요
6. 기업 마진
7. 달러/원자재
8. VIX/변동성
```

## 2. 기본 사용 흐름

```text
1. 데이터 업데이트
2. 웹사이트 배포
3. 8축 보기 확인
4. 선행/동행/후행 보기 확인
5. 수동 입력 항목 보완
6. 포트폴리오 상태 확인
7. 캘린더 이벤트 확인
8. 주간 리포트 생성
9. 백업
```

## 3. 데이터 업데이트와 배포의 차이

가장 중요한 구분이다.

```text
Update market dashboard data
→ data/latest.json, data/history.json 갱신
→ 숫자와 지표 데이터 업데이트

Deploy static dashboard to GitHub Pages
→ 웹사이트 화면에 반영
→ 사용자가 보는 페이지 업데이트
```

데이터 업데이트만 해도 화면이 바로 바뀌지 않을 수 있다. 배포까지 실행해야 한다.

## 4. 데이터 업데이트 방법

GitHub에서 다음 순서로 실행한다.

```text
Actions
→ Update market dashboard data
→ Run workflow
```

성공 후 확인할 파일:

```text
data/latest.json
data/history.json
```

## 5. 웹사이트 배포 방법

```text
Actions
→ Deploy static dashboard to GitHub Pages
→ Run workflow
```

배포 완료 후 브라우저에서:

```text
Ctrl + F5
```

을 눌러 강제 새로고침한다.

## 6. 수동 입력 항목

아래 항목은 완전 자동화하지 않고 수동 판단으로 남겨둔다.

```text
- M7 가이던스 변화
- 컨센서스 리비전
- Pricing Power 언급
- Fear & Greed Index 원본값
```

수동 입력은 단순 숫자 입력이 아니라 시장 해석을 보완하는 부분이다.

## 7. 포트폴리오 입력/수정

포트폴리오 패널에서 보유 자산을 입력한다.

입력 권장 항목:

```text
- 종목명
- 현재 금액
- 현금
- 메모
```

포트폴리오 기능은 수익률 계산보다 비중과 현금 여력을 확인하는 데 목적이 있다.

## 8. 월간 캘린더 사용법

캘린더에는 다음을 기록한다.

```text
- CPI
- PCE
- FOMC
- NFP
- ISM PMI
- 주요 실적 발표
- 주간 리포트 작성일
- 포트폴리오 점검일
```

캘린더 표시는 다음 의미를 가진다.

```text
파란 점: 경제/시장 이벤트
초록 점: 체크리스트 완료
주황 점: 주간 리뷰/리포트 기록
```

## 9. 주간 시장 리포트 생성법

위치:

```text
To do / 점검
→ FactSet + Investing.com + 8축 주간 리포트
```

입력 순서:

```text
1. 리포트 날짜 선택
2. 리포트 길이 선택: 1페이지 / 2페이지 / 3페이지
3. Investing.com 인기 뉴스 3개 제목 입력
4. 각 뉴스 링크 입력
5. 각 뉴스 요약 입력
6. 관련 8축 선택
7. 긍정/중립/부정/경고 판단 선택
8. 리포트 생성
9. 저장 또는 TXT 다운로드
```

리포트는 다음 내용을 자동 반영한다.

```text
- 8축 자동 신호
- FactSet EPS Beat Rate
- FactSet Revenue Beat Rate
- 주요 금리/고용/소비/VIX 지표
- 포트폴리오 현금 비중
- 캘린더 이벤트
```

## 10. 백업/복원

주 1회 또는 큰 수정 전에는 백업한다.

```text
To do / 점검
→ 백업 · 복원
→ 전체 데이터 백업
```

복원할 때는 이전 백업 JSON을 업로드한다.

주의:

```text
복원은 localStorage 데이터를 덮어쓴다.
중요한 현재 입력값이 있으면 먼저 백업 후 복원한다.
```

## 11. 추천 운영 원칙

```text
- 기능 추가는 천천히 한다.
- 매주 토요일 8축 판단과 리포트 생성에 집중한다.
- 이상한 수치가 보이면 먼저 데이터 소스 기준표를 확인한다.
- GitHub Actions 실패 시 로그를 먼저 확인한다.
- 정상 작동 버전은 항상 백업해둔다.
```
